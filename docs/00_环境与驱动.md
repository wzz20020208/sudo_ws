# 环境与驱动：gs_usb 内核模块补编

## 为什么必须用 RT 内核源码树编 gs_usb

`gs_usb` 是 CANable/gs_usb 类 USB-CAN 适配器的内核驱动。加载一个 `.ko` 时，内核要求
模块的 **vermagic** 与运行内核完全一致，否则报 `version magic mismatch`（就是常说的
「内核不匹配」）。

本机运行内核（`uname -r`）的 vermagic：

```
5.10.160-rt89+ SMP preempt_rt mod_unload aarch64
```

而 Orange Pi 原装 `rockchip-rk3588` 内核编出的 `gs_usb.ko` vermagic 是
`5.10.160-rockchip-rk3588 ... modversions`，直接拷到 RT 内核下加载会 mismatch。
所以**必须用本机 RT 内核的源码树编模块**，vermagic 才对得上。源码树位置：
`/root/linux-orangepi-5.10.160-rt`，`/lib/modules/<uname -r>/build` 就指向它。

## 一键脚本

```bash
bash tools/build_gs_usb.sh
```

脚本做了：定位源码树 → 确保 `CONFIG_CAN_GS_USB=m` → `make modules_prepare` →
只编 `drivers/net/can/usb/gs_usb.ko` → 装到 `/lib/modules/<uname -r>/.../can/usb/` →
`depmod -a` → 打印 vermagic 供核对。

## 手动标准流程（脚本内容逐条拆解）

```bash
# 1. 进 RT 源码树
cd /root/linux-orangepi-5.10.160-rt

# 2. 确认 gs_usb 配置为模块（=m），=y 是编进内核、不产 .ko
grep '^CONFIG_CAN_GS_USB=' .config        # 期望 CONFIG_CAN_GS_USB=m
# 若 =y 或缺失：
sudo sed -i 's/.*CONFIG_CAN_GS_USB.*/CONFIG_CAN_GS_USB=m/' .config   # =y → =m
# 缺失时 sed 不会新增，需追加：
echo 'CONFIG_CAN_GS_USB=m' | sudo tee -a .config
sudo make olddefconfig

# 3. 准备编译环境（若源码树没完整 build 过；已 build 过则幂等很快）
sudo make modules_prepare

# 4. 只编单个模块（不用全量编内核）
sudo make drivers/net/can/usb/gs_usb.ko
# 或编整个 usb 子目录：sudo make M=drivers/net/can/usb modules，产物一样

# 5. 安装 + 刷新模块依赖
sudo mkdir -p /lib/modules/$(uname -r)/kernel/drivers/net/can/usb
sudo cp drivers/net/can/usb/gs_usb.ko /lib/modules/$(uname -r)/kernel/drivers/net/can/usb/
sudo depmod -a
```

## 验证

```bash
modinfo -F vermagic gs_usb                 # 应等于运行内核 vermagic
sudo modprobe gs_usb                       # 或插上适配器让 udev 自动加载
ip link                                    # 应出现 can0（第二个适配器是 can1）
lsmod | grep gs_usb
```

## 接口配置

USB-CAN 适配器插上后接口**自动创建**，不要 `ip link add`（硬件接口已存在会报
`File exists`）。只配置参数并 up：

```bash
bash tools/can_setup.sh --ifname can0 --bitrate 1000000
# 双适配器：bash tools/can_setup.sh --ifname can0 --ifname2 can1 --bitrate 1000000
```

## 排查速查

| 现象 | 检查 |
| :-- | :-- |
| `modprobe` 报 version magic mismatch | 模块不是 RT 源码树编的，重编 |
| `ip link` 无 canX | `lsmod \| grep gs_usb`、`dmesg \| grep -i can`、适配器是否插好 |
| 接口在但起不来 | `sudo ip link set can0 type can bitrate 1000000 && up` |
| `modprobe` 无输出 | 多半已加载或 udev 自动加载了，`lsmod` 确认 |
