# WiFi 双机互 ping 不通排查：同一 SSID 挂在不同物理 AP

## 现象

两块 Orange Pi 5 Plus（主从跟随 ROS2 用）连同一个 WiFi SSID「sudo」，同一子网
`172.16.52.0/23`：

- 各自能 ping 通网关、其他电脑和其他客户端（.51/.60/.68 等）
- **互相 ping 不通**：广播 ARP 收不到、静态 ARP 单播也不通
- 直连网线（固定 IP）互相通，排除了驱动/协议栈问题

## 根因

「sudo」这个 SSID 由校园网**多台物理 AP 共用一个名字**（mesh 部署），各 AP 的
BSSID、通道都不同。两台板子各自关联到了**不同的物理 AP**：

| 板子 | BSSID | 频率 |
| :-- | :-- | :-- |
| 本板 | `AE:CE:88:BD:6F:F0` | 5745 MHz（5G ch149） |
| 对端 | `2E:CE:88:BD:6A:20` | 5825 MHz（5G ch165） |

校园网**不转发跨 AP 的无线客户端互访**：无线→有线（网关/其他电脑）都走正常路径，
无线→另一台 AP 上的无线则被丢弃。所以两台各自能上网，但互相的帧（广播 ARP、
单播数据）到不了对方。

## 关键证据

- 本板抓包：每秒广播 `Request who-has 172.16.52.128`，**无任何 reply**；
  同一时刻 `.60`/`.68` 正常应答 → 广播发得出去，但到不了对端所在 AP
- 对端抓包：能收到**单播** ARP（`.51` 发给它的 `Request`，它正常 `Reply`）→
  对端收单播没问题，唯独收不到本板广播
- 静态 ARP 强制单播后 ping 仍不通 → 单播帧在对方所在 AP 被丢，与「跨 AP 不转发」
  一致

## 排查过程中排除的方向

| 假说 | 结论 | 依据 |
| :-- | :-- | :-- |
| 路由器客户端隔离 | 排除 | 同 AP 下其他客户端（.60/.68）都能互相应答 |
| WiFi 省电 power save | 排除 | 两边 `set power_save off` 后仍不通 |
| 两板随机 MAC 相近 | 排除 | 改本板 MAC 为 `02:00:00:00:00:01` 后仍不通 |
| 静态 ARP 单播绕过广播 | 排除 | 强制 ARP 后 ping 仍 100% 丢 |
| 内核隔离 | 排除 | `ip rule`/`ip route` 均无策略路由，sysctl 默认 |

## 解法：两台钉到同一个物理 AP

对端已连 `2E:CE:88:BD:6A:20`，把本板也钉过去（命令在**两台板子**上都执行，BSSID
用同一个）：

```bash
nmcli con mod "wlan1" 802-11-wireless.bssid 2E:CE:88:BD:6A:20
nmcli con up "wlan1"
iw dev wlan1 link          # 确认两台 Connected to 同一个 BSSID
```

同 AP 内部互访即通，双向 `ping` 恢复。

> BSSID 先以对端当前 `iw dev wlan1 link` 输出的为准——若它已漫游到别的 AP，
> 两台都钉那个新 BSSID 即可。

### 本板 IP 固定（对端按固定地址访问）

钉到同 AP 后，本板若仍由 DHCP 拿 172.16.53.x 段，对端按旧地址 ping 不到；把本板
IP 固定到 172.16.52.x，对端就能用已知地址访问：

```bash
nmcli con mod "wlan1" ipv4.method manual ipv4.addresses 172.16.52.126/23 ipv4.gateway 172.16.52.1 ipv4.dns 172.16.52.1
nmcli con up "wlan1"
```

> 掩码必须 **/23**（该网横跨 172.16.52.x 与 172.16.53.x）；DNS 按校园网实际值替换。
> 设之前先 `ping -c 2 172.16.52.126` 确认地址空闲。

## 注意事项

- **钉 BSSID 会禁用漫游**：目标 AP 信号变弱或不可达时直接断连，不自动换 AP。
  跟随设备若需移动，稳妥方案是其中一块板自建热点（hostapd）、另一块接入，
  完全绕开校园网。
- 该结论依赖当前校园网拓扑。若换网络环境（自己路由器的单一 AP），通常无此问题，
  可直接互相 ping 通。

## 排查速查

| 现象 | 检查 |
| :-- | :-- |
| 同一 SSID 两台互 ping 不通，各自能上网 | 对比两台 `iw dev wlan1 link` 的 BSSID 是否一致 |
| BSSID 一致仍不通 | 查 AP 客户端隔离/防火墙 |
| BSSID 不一致 | 两台钉同一个 BSSID（见上） |
| 钉 BSSID 后断连 | 目标 AP 信号弱，改用自建热点方案 |
